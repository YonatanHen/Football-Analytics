# fetch_cli

Developer CLI for the Sofascore competition/season catalog. Lives outside `backend/`
on purpose — this is a standalone dev tool, not part of the shipped backend service.
It never talks to Sofascore/ScraperFC directly (that needs Chrome, which only the
backend Docker image has installed) — instead it calls the running backend over
HTTP at `http://localhost:8000` (configurable via `FETCH_CLI_BACKEND_URL` or
`--backend-url`).

Three commands:
- `refresh` — repopulate the local catalog from the backend
- `browse` — list competitions / seasons from the local SQLite catalog
- `fetch` — interactive: pick a competition, pick a season (both shown with
  `[fetched: ...]` / `[already fetched]` markers sourced from MongoDB's
  `league_meta`), confirm if re-fetching, then trigger and poll
  `POST /v1/fetch/` on the backend. No fetch rate limit — triggers immediately.

The catalog is a local SQLite file at `tools/fetch_cli/data/catalog.sqlite3`
(gitignored, regenerated by `refresh`) — it holds competition/season metadata only,
never player stats.

## Setup

The backend must be running (`docker compose up`, from the repo root) — `refresh`
calls it over HTTP.

This tool has its own lightweight venv, separate from `backend/.venv`:

```bash
cd tools
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
```

## Running

From `tools/`, with the venv activated (or by calling `.venv/Scripts/python` directly):

```bash
.venv/Scripts/python -m fetch_cli.cli refresh --only "England Premier League"   # quick single-competition test
.venv/Scripts/python -m fetch_cli.cli refresh                                   # full catalog (all competitions, slower)
.venv/Scripts/python -m fetch_cli.cli browse                                    # list all competitions
.venv/Scripts/python -m fetch_cli.cli browse "England Premier League"           # list seasons for one competition
.venv/Scripts/python -m fetch_cli.cli fetch                                     # interactive: pick league + season, load into MongoDB
```

Must run with `cwd = tools/` (or otherwise have `tools/` on `PYTHONPATH`) so the
`fetch_cli` package resolves.

## Tests

Pure-logic tests only (no network) — from `tools/`:

```bash
.venv/Scripts/python -m pytest fetch_cli/tests -v
```
